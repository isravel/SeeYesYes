# M7.3 Automated accessibility audit of all routes and relevant states

Date: 2026-10-14

`tests/browser/a11y-audit.spec.ts` runs axe-core against the production build on 53 states in light and dark appearance (106 combinations): the 17 main views and detail pages; the empty and error scenarios of every data-driven view; not-found; the Theme editor with a failing draft and with its preview dialog open; no-match states for Tokens, Components, Rules, and Docs; Validation with a failing report and a result open; AI Context with a task export and the Markdown tab; Component Detail with disabled, loading, and invalid states, plus an open Dialog, Menu, and Tooltip and tabs; the Playground in dark, compact, and curvy, and with its dialog open; Layouts in dark and compact; and the mobile navigation drawer. The full list and results are in [a11y-audit-results.md](a11y-audit-results.md), regenerated on every run.

**Result: 0 serious or critical findings.**

**Fixed during the audit**
- Component Detail's loading and error states had no page heading (the error scenario failed the audit's "ready" check). They now show an `h1` with the component's ID until the contract loads.
- Earlier tasks' axe journeys had already caught and fixed a page rule overriding an Alert's title color and a layout definition-list structure problem; the shared audit keeps them fixed.
- A manual review of the Switch found its off-state track was nearly invisible against some surfaces (a non-text contrast gap axe cannot measure). It now has a boundary in the border token and a muted-foreground knob (primary track with an on-primary knob when on), and its contract's token list was updated.

**Lesser findings, reviewed**
- `region` (moderate), 2 occurrences, only in the open Tooltip state: the tooltip's portal container sits outside the page landmarks. Resolution: no change. A tooltip is transient and is announced through its trigger's `aria-describedby`; placing popup text inside a landmark would not help assistive technology.

**One deliberate exclusion.** In the "failing draft" state the Theme editor's preview is excluded from axe: it shows the user's intentionally unreadable draft (foreground lightness 0.97), and the editor warns about it instead of hiding it. The failing contrast there is measured by the contrast check, which is covered by its own tests.

**Limits.** Automated checks find some problems and do not prove conformance. They do not replace manual keyboard and screen-reader testing (M7.4, which needs a human tester).
