# M7.6 Performance (A17): result and investigation

Date: 2026-10-16

**Result: passed under the recorded lab conditions.** All four routes meet the performance score, LCP, and CLS targets. Both interaction traces meet the long-task target. M7.6 and A17 close. Full conditions and samples are in [performance.md](performance.md) and [performance.json](performance.json).

The procedure uses the production build, fixed zero-latency mock endpoints, Lighthouse mobile with simulated throttling, and three runs per route with medians. The final gate ran `npm run check` (which builds the app), then the browser suite, then `npm run perf` without the browser suite competing for resources. Node was 24.22.0. No budget or measurement setting was relaxed.

The Theme and catalog interaction traces recorded no long task above 50 ms. A deliberate 120 ms busy loop was detected by the observer self-check before those traces.

## Earlier failure and investigation

The 2026-10-14 run missed the LCP target on all four routes (2.56–2.86 s). Scores, CLS, and the interaction targets already passed. A static HTML control painted in about 0.7 s under the same procedure, while static application routes missed by a similar margin to interactive routes. Shared JavaScript on the critical path was the main cause; Lighthouse identified unused JavaScript as the main opportunity.

Earlier work reduced shared page data by sending a slim theme system instead of the entire registry, delayed the mobile drawer and below-the-fold Overview previews, and kept unused Markdown code out of the agent-file module. The validation library still cost about 36 KB gzipped on the shared first-load path.

## Changes that closed the target

- `lib/theme/check.ts` validates theme settings and stored envelopes without loading zod on every page. Schema comparison tests cover the runtime checks. The final review added safe-integer boundaries for revisions, including the early bootstrap path.
- Data views load the validating HTTP adapter on the first request through `lib/data/lazy-adapter.ts`. Response validation remains in place.
- The AI Context export builder loads separately from the page shell, keeping its validation and export code off the initial paint path.
- Inter uses the locally shipped variable font. There is no styling runtime, optional editor, or motion toolkit in the dependencies.

The performance report records all script requests observed by Lighthouse, including work loaded after the initial paint. Those transfer totals are not a measurement of the first-load bundle alone.

The final gate also corrected `scripts/perf.mjs`: it now exits with status 1 when either route budgets or interaction budgets fail. A completed measurement with a failed budget can no longer look like a successful command.

These are lab results on one machine, not a real-user performance claim. Human accessibility and visual review remain separate open checks.
