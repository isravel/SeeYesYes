# M7.5 Viewport, zoom, appearance, density, radius, motion, and style-ownership review

Date: 2026-10-14

**Viewports (A14).** `tests/browser/review-matrix.spec.ts` loads 14 representative screens at 320, 768, 1280, and 1920px in light and dark with no page-level horizontal overflow. A 640px layout viewport (the 200% zoom proxy for a 1280px window; it is a viewport proxy, not a literal browser zoom) also reflows every one of those screens without overflow, and the Theme editor and mobile navigation stay operable there.

**Radius and density.** All nine combinations of sharp, soft, and curvy radius with compact, comfortable, and spacious density render the Theme preview in light and dark at 320 and 1280px with no overflow, and the resolved variables match each setting (radius 0, 0.5, and 1rem; row height 2.75, 3, and 3.5rem). Four representative combinations are saved as screenshots in `screenshots/` (sharp-compact light, soft-comfortable dark, curvy-spacious light, curvy-compact dark). Earlier milestones check all scale settings in unit tests, and the intentionally failing draft visibly warns (M3.6).

**Motion.** Reduced motion removes transitions and animations in the workspace and inside the preview scope even with a motion setting enabled (M3.7 and the integration checks, still passing).

**Style ownership (OOCSS).** `tests/oocss.test.ts` audits every component stylesheet: no raw color literals (appearance comes from semantic tokens), no `:global`, no `!important`, no selector that reaches outside the component's own classes, variants expressed as data attributes on one base rule (no parallel variant classes, and each variant selector has a base rule it adds to), and geometry taken from shared scales. It found a `!important` in Table and a hard-coded radius in Link's focus ring, both fixed (Link now uses the radius token and its contract lists it). The one documented exception is Switch's pill-shaped track. Separately, the page-and-layout audit from M6 found and fixed descendant selectors that reached into live component demos.

**Standalone, nested, and overlay.** A browser test compares computed styles under the same theme: a Button standalone (component page) and nested in a settings layout are identical in every compared property (font, padding, radius, colors, height, border, shadow), and the Button inside an open Dialog has the same font size, radius, and height; Input and Card are likewise identical standalone and nested. Parent-owned placement is allowed to differ and is not compared.

Verification: `npm run check` passed (392 unit tests, 6 new) and all 159 production browser tests passed. Human visual review and screen-reader testing remain open.
