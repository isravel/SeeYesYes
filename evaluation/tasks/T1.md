# T1 · Account settings form

## Prompt

On the account page, add a settings form where someone can change their name and email, pick which plan they are on (Free, Team, or Business), and choose whether to get the monthly newsletter. Add a way to save it. If the email is left empty or has no @ sign, tell the person what is wrong when they try to save. Keep it consistent with the rest of the app.

## Expected components

Form Field, Label, Input, Select, Switch, Button

## Rules and behavior probed

- Every field has an associated, visible label.
- Error text is shown and tied to the field it describes.
- The save action is a submit button inside the form (`type="submit"`).
- `token-no-raw-color`: no raw color literals outside design tokens.

## Requirements checklist

- [ ] Name, email, plan, and newsletter controls all exist and work.
- [ ] Each control has a programmatically associated label.
- [ ] Submitting with an empty or invalid email shows a specific error message next to the email field and marks the field invalid.
- [ ] The save control is a button of type submit that submits the form with the Enter key.
- [ ] The plan choice offers Free, Team, and Business.
- [ ] No hard-coded color values appear in the added code.
